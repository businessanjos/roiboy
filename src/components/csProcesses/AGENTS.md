# AGENTS.md — src/components/csProcesses

- CS process steps render one at a time from typed actions derived by `toStepInfo` (src/lib/csProcessActions.ts) over the unchanged markdown format. Why: clearer reading without changing the text managers edit.
- The "Em andamento" tab is a read-only board built by `useCsInProgress` from existing fields: onboarding step comes from the client's Onboarding Hub stage via `stepOfStage` (unmapped stages show as "Sem fase definida") and event steps from the event date via the shared offsets in `src/lib/csToday.ts`. Why: Processos is the team's map; work happens in the existing CS areas, so nothing is invented or counted here.
- Example links in process texts are swapped per client by `resolveProcessLink` (src/lib/csClientLinks.ts); the markdown keeps the example URLs. Why: managers keep editing one text while each client gets her own links.
- Managers edit one step at a time (StepEditDialog via hover pencil in StepNavigator); saving re-serializes all processes with `serializeProcesses` into `cs_process_content`, never exposing the raw source document. Why: editors change messages, not the source prompt.
- "Em andamento" shows all consultants only to management or users with override `cs`/`processos_ver_todas` (granted in Configurações > permissões por usuário via the catalog item); page opens on "Processos". Why: consultants see their own clients unless a manager grants more.
- O gravador de áudio dos Processos (StepDetail → AudioTeleprompter) envia como nota de voz pelo `sendProcessAudio` (src/lib/csAudioSend.ts), usando a conversa 1:1 da cliente no RoyZapp com media_type ptt. Por quê: assim a cliente recebe áudio "gravado agora", nunca um arquivo ou encaminhado.
- For a selected client in the Onboarding process, the Onboarding Hub stage (`clients.stage_id`) is the source of truth: steps before its mapped step count as done (`impliedDoneKeys`), so the screen opens at the client's real step, and marking steps moves the client forward via `stageToAdvance` (never backward). Why: Processos is mostly for consulting, so it must mirror the Hub without duplicate work.
- The "Clínica Ryka" step of `OnboardingMeetingGuide` shows the real Ryka wordmark (`Block.logo` from `src/assets/ryka-logo.png.asset.json`, dark on transparent) instead of a lucide icon, and keeps `dark:brightness-0 dark:invert` on the `<img>`. Why: the stored mark is dark, so without the filter it disappears on the dark-mode tile.
- Steps in `StepNavigator` preview on hover via `StepPreview` (read-only, first 5 actions, `toStepInfo` computed only while open), and `HoverCardContent` wraps its content in `HoverCardPrimitive.Portal`. Why: the navigator sits in a sticky stacking context, so inline popper content painted under the step panel.
- "Processo concluído" = `isProcessFinished` (src/lib/csProcessDone.ts): todas as `allKeys` feitas (progresso salvo ou etapa implícita do Hub). Nesse estado a barra de rodapé é substituída por `ProcessFinishedCard`, que pulsa uma vez (`celebrateFinish` → `cs-done-pulse`, ~9s) só no momento em que o processo fecha; sem cliente, a última etapa mostra o selo "Fim do processo". Why: o botão antigo era fraco demais e a consultora não percebia que de fato acabou.
- O `GuidedTour` trata ← → do teclado no listener `window` em fase de captura (avança/recua passo; no último, fecha) e mantém o foco dentro do balão (`focusin` + intervalo de 300ms puxando o botão primário de volta). Why: o iframe do painel 3C Plus rouba o foco e engolia as teclas, e o realce de foco é o anel dourado (`ring-primary/55`), nunca o contorno preto do navegador.
- Processos (etapas Plano de Ação e Ciclo mensal) show read-only Ryka usage via `RykaUsagePanel` from the latest `client_ryka_usage_daily` row of the selected client. Why: consultants see the real plan/usage without leaving the step.
