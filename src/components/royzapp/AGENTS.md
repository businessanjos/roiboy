# AGENTS.md — src/components/royzapp

- Internal team numbers (registered in `zapp_internal_contacts` plus collaborator phones, compared through `zappPhoneCore`) are not client service: `ZappConversationItem` hides the wait badges and `ZappChatHeader` shows "Interno" instead of a client-waiting status. Why: `zapp_productivity_metrics` already drops those numbers, so the UI must not present a colleague as a client waiting.
- Account-wide RoyZapp settings live in `zapp_account_settings` (members read, admins write); `zapp-ruler-dispatcher` reads it server-side. Why: background sends cannot see browser preferences.
- In the group composer, a pasted "@Nome" becomes a real WhatsApp mention when it matches exactly one participant (WhatsApp name or client-record name found by number); when nobody matches, the name is removed and only "@" is left so the participant list opens for manual picking. Why: a name that could not be resolved must never be sent as a fake mention.
- WhatsApp profile photos are stored as permanent copies in `zapp-media/avatars/<conversation_id>.jpg` by the scheduled `zapp-avatar-sync` (small batches, UAZAPI `/chat/details` for missing/expired photos, `avatar_checked_at` to avoid rechecking within 24h). Why: `pps.whatsapp.net` links expire in days, so storing them raw left most chats without a photo.
- O limite de mensagens por hora do RoyZapp é por setor em `zapp_sector_message_limits` (fixo + "só hoje" até a meia-noite de Brasília, de 20 a 300). Só quem é gestor/admin do próprio setor pode alterar (`zapp_sector_role`), e cada mudança vai para `zapp_sector_message_limit_history` por trigger. O quadro só aparece no setor Vendas. Why: um admin de outro setor não pode mexer no limite de Vendas, e quem mudou fica registrado.
- No setor Vendas, "Puxar" (de outro atendente ou da fila/triagem) por quem não é gestor (`zapp_can_pull_directly`, `needsPullApproval`) abre um pedido (`request_zapp_conversation_transfer`); o gestor decide no ROY (`/transferencia-conversa/:id`) ou pelos botões `ztr:*` no WhatsApp, ambos via `decide_zapp_transfer_core`, que transfere e avisa o vendedor. Why: uma só regra de aprovação, como nas transferências de negócio.
- The Equipe tab lists only active attendants (inactive behind "Mostrar inativos"); Inativar/Reativar go through the RPC `set_zapp_agent_active`, which reuses `release_zapp_assignments_for_user` so open chats return ownerless to the queue. Role badges come from `resolveTeamRoleBadges` (all `user_team_roles`, legacy `users.team_role_id` only as fallback). Why: one release path for every deactivation, and the badge must match the roles ticked in Settings > Team.
- Playbook items that go out as text (text, link, list, template) take their content only from `playbookItemRawText` (src/lib/playbookItemText.ts) in single send, multi-send, "/" shortcut, sequences and the phone preview; variables are applied over that text. Why: Template and Lista keep their content outside `text_content`, so reading that field alone made the send fail with "sem conteúdo".
- Clickable template buttons are opt-in per Playbook template (flag stored on the `template_buttons` entries, read via `templateButtonsClickable`); `templateMenu` splits message/footer/buttons, the composer keeps them as a pending menu tied to the text in the input, and `uazapi-manager` `send_text` with `menu` tries `/send/menu` and falls back to the full text. Sequences carry the same split in `zapp_sequence_run_steps.menu` (snapshot at start, `text_content` stays the full text) and `zapp-sequence-dispatcher` applies the same try-then-text rule. Groups and the Meta channel always send the text form. Why: no schema change, the send keeps every `send_text` guard, and a refused button send must never lose the message.
- The Régua screen (`ZappRulerPanel`) searches, filters and sorts through `src/lib/zappRulerFilters.ts` over rows already loaded, and touch actions (concluir, pular, excluir, encerrar) patch local state instead of refetching. Why: a full refetch swaps the panel for a loader, which closes the open ruler and resets tab and page.
