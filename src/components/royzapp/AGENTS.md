# AGENTS.md — src/components/royzapp

- Internal team numbers (registered in `zapp_internal_contacts` plus collaborator phones, compared through `zappPhoneCore`) are not client service: `ZappConversationItem` hides the wait badges and `ZappChatHeader` shows "Interno" instead of a client-waiting status. Why: `zapp_productivity_metrics` already drops those numbers, so the UI must not present a colleague as a client waiting.
- Account-wide RoyZapp settings live in `zapp_account_settings` (members read, admins write); `zapp-ruler-dispatcher` reads it server-side. Why: background sends cannot see browser preferences.
- In the group composer, a pasted "@Nome" becomes a real WhatsApp mention when it matches exactly one participant (WhatsApp name or client-record name found by number); when nobody matches, the name is removed and only "@" is left so the participant list opens for manual picking. Why: a name that could not be resolved must never be sent as a fake mention.
- WhatsApp profile photos are stored as permanent copies in `zapp-media/avatars/<conversation_id>.jpg` by the scheduled `zapp-avatar-sync` (small batches, UAZAPI `/chat/details` for missing/expired photos, `avatar_checked_at` to avoid rechecking within 24h). Why: `pps.whatsapp.net` links expire in days, so storing them raw left most chats without a photo.
- O limite de mensagens por hora do RoyZapp é por setor em `zapp_sector_message_limits` (fixo + "só hoje" até a meia-noite de Brasília, de 20 a 300). Só quem é gestor/admin do próprio setor pode alterar (`zapp_sector_role`), e cada mudança vai para `zapp_sector_message_limit_history` por trigger. O quadro só aparece no setor Vendas. Why: um admin de outro setor não pode mexer no limite de Vendas, e quem mudou fica registrado.
