- Office TVs: ROY stores config/commands in `tv_*` tables (managers via `tv_can_manage`); the LAN agent only talks to edge function `tv-agent` (header `x-agent-token`). Why: ROY cannot reach the TVs; agent contract must stay stable.
- TV connection quality lives in `tv_status` (agent-written, absent fields keep prior value) with a 5-min/7-day trail in `tv_conn_history`; "Liberar TV" writes `tv_screens.released_until` only through RPC `tv_release`, which also logs the event with the user name. Why: tv_events is read-only to managers and the agent reads release state from screens.
- Rest screen: static ES5 `public/tv-descanso.html` (default `rest_url`, for old webOS/Chromium 53 TVs) mirrors React /tv/descanso; both are public (no login) and reads only images/switch times via public edge function `tv-rest-public`: main day/night image (asset defaults, overrides `tv_settings.rest_day_image/rest_night_image`, times `rest_day_from/rest_night_from`, Brasília) plus `rest_extra` [{path, period}] rotating with the main image of the same period; "all to rest" clears `tv_screens.url` keeping `rest_prev_url`. Why: TVs may be logged out; agent shows rest on TVs without url.
- "Adicionar TV" (admins only, disabled when agent last sync >2 min): wizard inserts `discover` / `pair` / `pair_code` into `tv_commands` and polls the row; `tv-agent` stores object results as JSON text. Pure rules in `src/lib/tv/addTv.ts`. Cancel deletes the created screen. Why: agent does the network work; ROY only queues and shows progress.
- TV images: "Imagem" content uploads PNG/JPG (PDF → page 1 via pdf.js in browser) to private bucket `tv-media` (public buckets are blocked), listed in `tv_media` ("Mídias"); TVs open static ES5 `public/tv-imagem.html?src=<tv-media-public redirect>&fit=contain|cover`. Optional `image_until` with `previous_url` is restored by `tv-agent` on sync. Why: old TVs need no-React pages and expiry must work without anyone online.
- Central de Tráfego (external `eternum-luxe-hub`) links are built/parsed only by `src/lib/tv/trafficHub.ts`; they appear as two extra options in the Dashboard select, agency/period changes save the TV url immediately, and the agency list is read from `tv_settings.traffic_agencies` (built-in defaults when empty) with no editing UI in the TV panel. Why: links pasted by hand must read back legibly and one place owns the URL format.
- The wall toolbar has exactly one release control: "Liberar todas" (`ReleaseMenu` in `TvConnRelease.tsx`), and "Devolver todas (N)" is a line inside that same menu shown only while `releasedSlots` is non-empty; per-TV release/return stays on the card. Why: two toolbar buttons for one action read as a bug to managers.
- "Início do mês": tv-agent swaps a monthly period for the annual one in the served url (never the stored url) via `supabase/functions/_shared/tvMonthStart.ts`, which the card badge also imports. Why: one rule in São Paulo time for agent and UI.
- YouTube mini player: tv-agent stores sync `now_playing` per TV in `tv_status.now_playing` (TVs absent from the list are cleared); card shows `TvMiniPlayer` via `src/lib/tv/nowPlaying.ts` and sends media_* commands through `tv_commands`. Why: agent is the only source of playback state.
- Office-hours countdown (hero on the TV wall + compact block in "Horário do escritório") is one pure function `computeCountdown` in `src/lib/tv/officeCountdown.ts` (São Paulo, order keep_off > keep_on > holiday > weekday > hours, 60-day search) driven by `useOfficeCountdown`, which ticks locally and recomputes only on settings change, target reached or tab visible. Why: both views always show the same number and match the agent.
- TV keys: `tv_screen_tokens` keeps only nonce + sha256 per slot; value = HMAC(TV_TOKEN_SECRET, slot:nonce) from `_shared/tvToken.ts`, issued/revoked only by edge function `tv-token` (TV managers) and appended by tv-agent after the annual swap. `?tv_token` without a session renders `TvInsightsView` via `shared-insights` action `tv_load` (read-only, updates last_used_at). Why: TVs keep working when sessions expire without the key ever becoming a user session or being stored in clear.
