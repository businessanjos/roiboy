
- Permissões granulares: Perfis de Permissão (`permission_profiles`/`_items`, `user_permission_profiles`, `user_permission_overrides`, RPC `get_user_permissions`, hook `useUserPermissions`). Why: gestor libera por módulo/alcance, no modelo da Clínica Ryka.
- Visibilidade de negócios via RLS restritiva `can_view_deal` (dono/SDR/renovação/criador, gestor, perfil com alcance "all" ou `user_deal_visibility`). Why: bloqueia todos os caminhos de acesso, não só a tela.
- Acesso por funil: `user_pipeline_access` (none/own/all por pessoa e funil; sem linha = own, então funil novo já nasce "Só os dele"); `can_view_deal(..., pipeline_id)` aplica: gestor > none > dono > all > regras por status. Why: gestor libera funil a funil sem configurar funis novos.
- Mobile nav active state uses `pickActiveNavIndex` (pathname + query) and the tab bar's visibility hook drives AppLayout bottom padding. Why: one active tab and no phantom space when the bar is hidden.
- CX queue forecasts use a pure display-only calendar aggregation in America/Sao_Paulo, while queue and audit lists use shared pagination and bounded scroll regions. Why: readable day-based metrics without rescheduling events or changing delivery rules.
- Client history dialogs share ClientHistoryTimeline for date-grouped presentation in America/Sao_Paulo. Why: consistent readable chronology without duplicating events or changing data access.
- New sector WhatsApp numbers are created via uazapi-manager `create_sector_instance` (admin-only, then QR via ConnectQRCodeDialog). Why: sectors without pre-made UAZAPI instances could never generate a QR Code.
- Trial notices share a presentation-only identity predicate; SidebarPlanInfo reads the account from useCurrentUser. Why: consistent internal notices without altering billing or subscription access.
- Department colors must render through `getDepartmentColor` (src/lib/zappDepartmentColor.ts), which maps stored color names to real CSS. Why: stored values like "primary"/"emerald" are not valid CSS, so using them raw paints invisible markers and breaks list alignment.
- Transfer favorites are presentation-only local preferences scoped by account and current user, applied after normal agent sorting. Why: personal ordering must not change other users' lists or transfer permissions.
- RoyZapp group read state is per user (`zapp_conversation_reads` + RPC `zapp_my_group_unread`, hook `useZappPersonalGroupReads`); the shared `unread_count` stays for 1:1 chats. Why: one person reading a group must not clear it for colleagues.
- Client daily WhatsApp summaries share supabase/functions/_shared/clientDailySummary.ts (1 ai_whatsapp checkin per client per Brasília day, updated in place; manual button via client-daily-summary-now with user auth). Why: manual and nightly runs must never duplicate.
